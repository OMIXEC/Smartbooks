# Offline compatibility baseline

Smartbooks baseline is the public commit `609dc0bb36debba93ad8c78cc8d6e80e75fa9105`. The Isumbooks auth and entitlement predecessor is app commit `eae6c7c675e4c66c7d01868ce22aa8f1fccd0364`. The passage route, schema, runtime pin and adapter were verified in the app working copy at that commit. They require a committed app revision before they can be cited as shipped or used as a release pin. [Smartbooks baseline commit](https://github.com/OMIXEC/Smartbooks/commit/609dc0bb36debba93ad8c78cc8d6e80e75fa9105)

## Identity, revision and source records

- Preserve stored item IDs verbatim, including IDs referenced by shelves, manuscripts, citations and app edition mappings. New file IDs take the form `c_` followed by 12 lowercase hex digits from SHA-256 of `<resolved absolute path>:<contentHash>`. A file's initial `contentHash` hashes the base64 representation of its bytes. Inline creation uses `content:<SHA-256 of raw string>` as the ID seed and has a null `sourcePath`. Add/import and sync reuse the ID and `addedAt` at the same resolved source path, including after a content change. Reprocess explicitly retains ID and `addedAt`. A moved file ingested as a new path receives a newly derived ID, so migration should carry existing records forward rather than derive their IDs again. [Storage and ID](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/store.ts#L29-L91), [source and hash derivation](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/ingest/index.ts#L33-L117), [add/import](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/items.ts#L366-L381), [reprocess](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/items.ts#L279-L293), [sync](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/scan.ts#L59-L95)
- The read `version` is the item's ISO `updatedAt`. Preserve values on migration and exact string comparison for `items put --expect-version`, which rejects a stale value with `VERSION_CONFLICT` before modifying pages. Page/whole replacement, append, metadata enrichment and re-ingestion update `updatedAt`. Sync can refresh it even with the same file hash. Whole replacement recomputes `contentHash`, while page replacement, append and metadata enrichment leave it as stored. Freeze the timestamp token's observed semantics without assuming atomic compare-and-set, a content-addressed revision or a revision-pinned continuation. [Edit commands](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/items.ts#L165-L246), [metadata updates](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/store.ts#L71-L77), [sync](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/scan.ts#L62-L81)
- Keep `library/items.json` metadata and each `library/pages/<id>.json` body (`pages`, `toc`), preserving ordered page numbers, labels, text and TOC references. Keep source type, source path, recorded hash, timestamps and existing metadata. File ingest reads the original at its recorded path and stores extracted pages. Original binaries need separate retention. Removing indexed records leaves originals alone. Ordinary sync preserves records for missing files, while explicit `--prune` removes missing file-backed records and skips inline items. Malformed JSON fails instead of presenting an empty library. [Item fields](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/types.ts#L1-L36), [indexed files and removal](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/store.ts#L29-L86), [pruning](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/scan.ts#L86-L97), [JSON handling](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/util.ts#L85-L100)

## CLI and MCP wire contracts

- Preserve CLI `items list` as `{items}` with indexed metadata and TOC, `items toc` as `{id,title,toc}`, `items search` as `{query,hits}`, and `items cite` as `{verified,id,page,quote,title}` with a failing exit status for an unverified quote. A single successful `items read` result or `items get` yields `{id,title,version,pages,next}`. When the number of successful read targets differs from one, the wrapper is `{items:[...]}`. A missing single item gives `NOT_FOUND` and exit 1. Default reads cover up to the first ten pages. `read --all` sets the whole-item range when no narrower range is specified. [CLI read/list/TOC](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/items.ts#L27-L119), [search and cite](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/items.ts#L296-L347), [missing item](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/items.ts#L399-L406), [default range](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/common.ts#L131-L135)
- `sbs mcp` exposes stdio tools `list_books`, `book_toc`, `read_pages`, `search_books` and `verify_quote`. Preserve JSON encoded in the text result block, `nextOffset` for list pagination, 1-based `first`/`last`/`part` for reading, and the MCP-specific `stopped` field. `read_pages` rejects reversed or past-end starts and clamps the end to the item size. Search emits `{hits:[{id,title,page}]}` and quote verification uses indexed, whitespace-collapsed, case-insensitive substring matching. [MCP registration](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/cli.ts#L37-L40), [MCP input and replies](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/mcp.ts#L8-L89)
- CLI and MCP share a 20,000-byte UTF-8 text budget per item result, excluding JSON framing. Preserve 1-based page entries `{n,text}`, optional `part` and `parts`, and `next: {pages:"start-end",part?} | null`. Split at Unicode code-point boundaries, carry the requested end through each split page, remove `part` when moving to another page, and reject invalid part indices. Follow the returned range and part until `next` is null. This reconstructs indexed text for an unchanged item in order. PDF text extraction and EPUB spine text do not establish OCR, image or layout fidelity. [Shared reader](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/commands/common.ts#L60-L129), [PDF extraction](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/ingest/pdf.ts), [EPUB spine](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/src/ingest/epub.ts#L40-L79)

## Isumbooks passage boundary

- `GET /v1/books/{reference}/passages/{page}` requires verified Firebase bearer identity, including for free editions. Resolve a published edition for the requested locale using canonical ID, slug or alias. Premium/default access requires a future timezone-aware entitlement for that UID. Missing sign-in yields 401, unavailable account or missing premium entitlement yields 403, unavailable edition yields 404, and ambiguous references yield 409. Verify access before the adapter on every continuation request. First-party app sources at `eae6c7c67` are `backend/src/sumbooks/core/auth.py:13–22`, `application/catalog.py:7–36` and `infrastructure/catalog_store.py:15–19,36–41`. Current passage wiring is in working-copy `backend/src/api/routes/canonical.py:52–57`.
- The working-copy adapter requires explicit approval, an item ID matching `c_[0-9a-f]{12}` and a Smartbooks mapping version equal to the catalog edition version. It runs the pinned CLI with `--page`, `--part`, `--json`, `--no-session`, a minimal environment with isolated library home, and a five-second timeout. It rejects unexpected item/page IDs, invalid result text and CLI failures without returning extracted text. The API validates pages 1–10,000, part ≥1 and offset ≥0. It returns `{book_id,version,page,text,next}` with up to 4,000 Python characters and same-page continuation `{part,offset}` or null. `version` here is the published edition version. The adapter currently does not compare the CLI's returned revision to an approved source revision or pin it across continuations. Evidence is working-copy `backend/src/infrastructure/ismartbooks.py:12–52` (SHA-256 `2677b10d4363bd903ffd75eac5254ee9ae04967e55950237f3731e20085fca7a`), `backend/src/api/schemas/canonical.py:152–162` and `backend/smartbooks/package-lock.json:11,56`.

## Synthetic fixture plan and verification

1. Seed an isolated legacy-format home with a fixed synthetic ID, timestamps, source metadata, shelf entry, page labels and TOC. Compare metadata/IDs and page hashes before and after opening, same-path reimport and reprocess. Assert successful current-version writes and stale-version failure without page changes. Compare original-file byte hashes before and after reads and index removal. Assert ordinary sync retains a missing-source record and only explicit prune removes it.
2. Use authored Markdown and EPUB fixtures with more than ten pages, empty pages, an oversized page, combining characters, emoji and RTL text. Capture CLI JSON and MCP tool replies, follow every range/part token, then compare per-page text or hashes to the complete indexed text, including page order and text immediately after a split page. Include negative cases for unknown items, bad parts, invalid MCP ranges, invalid EPUB spine and corrupt index. [Existing generated regression fixtures](https://github.com/OMIXEC/Smartbooks/blob/609dc0bb36debba93ad8c78cc8d6e80e75fa9105/test/smartbooks.test.mjs#L18-L169)
3. Use an in-memory catalog, fake identities and a deterministic clock for free, valid premium, expired premium and no-entitlement cases. Cross-check wrong locale, unpublished or ambiguous editions, invalid mapping, timeout, mismatched item/page reply, out-of-range offset and auth revoked between chunks. Assert no CLI call for denied access, each returned text length ≤4,000 characters, stable response metadata, and exact reconstruction of one page using a real pinned CLI against a generated temporary home. Keep the existing mocked adapter tests for failure paths. Add a source-change-between-chunks case as a gap check if a future design claims revision-pinned continuity.

Current checks passed 9 standalone tests and 7 targeted app tests. The app tests cover the route's denial path, edition-version mismatch and two-level continuation using a mocked CLI. A real adapter-to-CLI integration test and migrated fixture for original identity and version semantics are still needed.
